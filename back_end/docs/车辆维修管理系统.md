# 课程实践项目——车辆维修管理系统 fileciteturn1file1

## 一、概述

车辆维修管理系统是面向维修业务的综合性数据库应用系统，旨在：

- **提升维修管理效率**  
- **降低运营成本**  
- **向客户提供更优质的服务**

系统整合 *车辆信息管理、客户信息管理、维修工单管理、库存管理、财务管理* 等核心模块，实现数据的实时共享与高效流转。fileciteturn1file1

---

## 二、系统功能需求

### 1. 用户功能

- 注册与登录系统  
- 提交车辆报修信息  
- 查询账户、车辆、维修记录与工单  
- 对维修进度与结果进行反馈（催单、评分等）  
- 查看历史维修记录 fileciteturn1file1

### 2. 维修人员功能

- 登录系统并查看个人账户信息（工种、时薪）  
- 接收或拒绝系统分配的维修工单（拒绝后系统重新分配）  
- 记录维修过程中消耗的材料及价格  
- 更新维修进度与结果  
- 查询历史维修记录与工时费收入 fileciteturn1file2

### 3. 系统管理员功能

- 维护用户、维修人员、车辆与维修工单信息  
- 保证数据一致性与完整性  
- 监控系统数据运行状况与统计结果 fileciteturn1file2

---

## 三、系统工作流程概述

1. 用户注册／登录后提交维修申请  
2. 系统生成维修工单并自动分配给维修人员  
3. 维修人员接单、记录材料及进度并提交结果  
4. 工单完成后，系统自动计算费用（工时费 + 材料费）  
5. 用户查询维修记录并提交服务反馈  
6. 系统管理员全程监控与维护流程 fileciteturn1file2

## 四、查询与数据分析需求

### 1. 基础查询需求（按角色）

| 角色 | 典型查询内容 |
| ---- | ------------ |
| **用户** | 账户信息、车辆信息、维修工单、历史维修记录 |
| **维修人员** | 账户信息（含工种与时薪）、当前与历史工单、累计工时费收入 |
| **系统管理员** | 全部用户／维修人员／车辆／工单信息及历史记录、工时费发放记录 | fileciteturn1file3

### 2. 进阶统计与分析需求（示例）

- 统计各车型的维修次数与平均费用  
- 车型维修统计：维修频率、常见故障类型  
- 成本分析：按季度／月份分解工时费与材料费  
- 筛选负面反馈工单及相关员工  
- 不同工种任务量占比（辅助招聘决策）  
- 未完成维修任务数量与类型（按工种／人员／车辆等维度）  
- **数据维护联动**：  
  - 工单状态改为"已完成"时自动汇总费用  
  - 用户／维修人员信息变更时历史记录同步  
  - 工单删除时级联删除关联记录  
- **事务控制**：批量提交与回滚保障数据一致  
- **数据回滚**：关键变动可追溯 fileciteturn1file0

## 五、系统中间件架构

### 1. 认证中间件 (Authentication Middleware)

**文件位置**: `src/middleware/auth.js`

**功能说明**:
- JWT令牌验证和管理
- 支持三种用户角色：customer（客户）、mechanic（技师）、admin（管理员）
- 用户状态验证（active、inactive、suspended）
- 令牌生成和刷新功能

**使用方式**:
```javascript
const { authMiddleware, optionalAuth } = require('./middleware/auth');

// 强制认证
router.get('/protected-route', authMiddleware, async (ctx) => {
  // ctx.state.user 包含用户信息
});

// 可选认证
router.get('/public-route', optionalAuth, async (ctx) => {
  // ctx.state.user 可能为null
});
```

### 2. 基于角色的访问控制中间件 (RBAC Middleware)

**文件位置**: `src/middleware/rbac.js`

**功能说明**:
- 基于角色的精确权限控制
- 支持资源所有权验证
- 车辆维修系统专用访问规则
- 多层次权限验证

**使用方式**:
```javascript
const { requireRole, checkVehicleRepairAccess } = require('./middleware/rbac');

// 角色检查
router.get('/admin-only', requireRole(['admin']), async (ctx) => {
  // 只有管理员可以访问
});

router.get('/customer-mechanic', requireRole(['customer', 'mechanic']), async (ctx) => {
  // 客户和技师都可以访问
});
```

### 3. 日志记录中间件 (Logger Middleware)

**文件位置**: `src/middleware/logger.js`

**功能说明**:
- 请求/响应日志记录
- 业务操作日志
- 审计日志
- 敏感信息过滤
- 按角色分类记录

**使用方式**:
```javascript
const { createLogger, logBusinessOperation } = require('./middleware/logger');

const logger = createLogger('ModuleName');

// 记录业务操作
logBusinessOperation('WORK_ORDER_CREATE', { orderId: '123' }, user);

// 模块日志
logger.info('操作成功');
logger.error('操作失败', error);
```

### 4. 错误处理中间件 (Error Handler Middleware)

**文件位置**: `src/middleware/errorhandler.js`

**功能说明**:
- 统一错误处理和响应格式
- 业务错误分类
- 中文错误消息
- 开发/生产环境区分
- 车辆维修系统特定错误类型

**使用方式**:
```javascript
const { createError, createBusinessError } = require('./middleware/errorhandler');

// 通用错误
throw createError.validation('数据验证失败', details);
throw createError.notFound('资源不存在');

// 业务错误
throw createBusinessError.workOrderNotFound();
throw createBusinessError.insufficientInventory('刹车片');
```

### 5. 中间件组合策略

**在 app.js 中的应用顺序**:
```javascript
// 1. 日志记录（最外层）
app.use(loggerMiddleware);

// 2. 错误处理
app.use(errorHandler);

// 3. 基础中间件（CORS、body parser等）
app.use(cors());
app.use(bodyParser());

// 4. 静态文件服务
app.use(createStaticMiddleware());

// 5. 可选认证
app.use(optionalAuth);

// 6. 车辆维修系统访问控制
app.use(checkVehicleRepairAccess);

// 7. 路由
app.use(router.routes());

// 8. 404处理（最内层）
app.use(notFoundHandler);
```

**在路由中的应用**:
```javascript
// 客户路由 - 需要customer或admin角色
router.get('/api/v1/users/me', 
  authMiddleware,           // 强制认证
  requireRole(['customer', 'admin']), // 角色检查
  async (ctx, next) => {
    // 业务逻辑
  }
);

// 管理员路由 - 只有admin可以访问
router.get('/api/v1/admin/users',
  authMiddleware,           // 强制认证
  requireRole(['admin']),   // 只有管理员
  async (ctx, next) => {
    // 管理员业务逻辑
  }
);
```

### 6. 安全特性

- **多层认证**: 令牌验证 + 角色验证 + 资源权限验证
- **审计追踪**: 所有操作都有完整的日志记录
- **错误安全**: 生产环境不泄露敏感信息
- **状态管理**: 支持用户状态控制（激活/禁用/暂停）
- **资源隔离**: 用户只能访问自己的资源
